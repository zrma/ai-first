# Open questions

## 결정된 범위

- spec은 설계 정합성을 확보하는 계약이며 단순 작업 목록이나 영구 완료 보고서가 아니다.
- 완료 artifact는 앞으로 필요한 지식의 위치에 맞춰 선택한다. milestone마다 별도
  결과 문서를 의무화하지 않는다.
- 자동 검사는 terminal active packet과 깨진 참조를 판정한다. 지식 이관의 의미적
  충분성은 spec과 실제 결과를 대조하는 검토로 확인한다.

## 남은 경계

- 공개 release version 확정, framework push/tag와 소비 저장소별 push는 검증된
  구체적 변경을 준비한 뒤 publication 권한에 맞춰 진행한다.
